# KMG天気予報 実装設計書

## 1. 文書の目的

この文書は、開発経験が少ない人やAIが、KMG天気予報と同等のサイトを再現・保守できるようにするための設計書です。

対象サイト：[KMG天気予報](https://tenki-compass.sukeaki.chatgpt.site/)

## 2. サービス概要

### 2.1 解決する課題

天気予報サービスごとに予報が異なる場合、利用者は「結局、傘が必要なのか」を判断しにくくなります。本サイトは4つの予報モデルを比較し、平均・多数派・ばらつきを一つの結論にまとめます。

### 2.2 主な機能

1. 今日・明日の総合予報
2. 4モデルの比較と信頼度
3. 24時間の1時間別予報
4. 傘が必要な時間の判定
5. 雨の開始・終了予測
6. 7日間の週間天気
7. 全国の主要都市の天気表示
8. 市区町村名・郵便番号による地点検索
9. GPSによる現在地取得
10. 雨雲レーダー
11. 気象庁の警報・注意報
12. 1時間ごとの自動更新

## 3. システム構成

```text
利用者のブラウザ
  ├─ KMG天気予報の画面
  ├─ GPS
  └─ 各外部APIへデータを取得
       ├─ Open-Meteo：4モデルの予報
       ├─ 気象庁：警報・注意報、地域コード
       ├─ Geolonia：市区町村と座標
       ├─ ZipCloud：郵便番号検索
       ├─ 国土地理院：現在地の住所判定
       └─ RainViewer：雨雲レーダー
```

サーバー側のデータベースは使用しません。表示時にブラウザから最新情報を取得します。

## 6. 外部データ設計

### 6.1 Open-Meteo

基本URL：

```text
https://api.open-meteo.com/v1/forecast
```

使用する予報モデル：

| 表示名 | modelsに指定する値 |
|---|---|
| 気象庁 JMA | `jma_seamless` |
| NOAA GFS | `gfs_seamless` |
| ECMWF IFS | `ecmwf_ifs025` |
| DWD ICON Global | `icon_global` |

主なリクエスト項目：

```text
timezone=Asia/Tokyo
forecast_days=7
forecast_hours=24
daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_probability_max,wind_speed_10m_max
hourly=precipitation_probability,precipitation,wind_speed_10m
```

短時間降水予測：

```text
minutely_15=precipitation
forecast_minutely_15=5
```

取得失敗時は、古い数値を正しい予報として見せず、「取得できませんでした」と表示します。

### 6.2 気象庁

警報・注意報：

```text
https://www.jma.go.jp/bosai/warning/data/warning/{officeCode}.json
```

地域コード：

```text
https://www.jma.go.jp/bosai/common/const/area.json
```

表示レベルは次の順序です。

```text
特別警報 > 警報 > 注意報 > 発表なし > 取得エラー
```

### 6.3 地点検索

市区町村一覧：

```text
https://geolonia.github.io/japanese-addresses/api/ja.json
```

市区町村の座標：

```text
https://geolonia.github.io/japanese-addresses/api/ja/{都道府県}/{市区町村}.json
```

郵便番号検索：

```text
https://zipcloud.ibsnet.co.jp/api/search?zipcode={7桁の郵便番号}
```

### 6.4 GPSと住所判定

ブラウザの `navigator.geolocation.getCurrentPosition` を使用します。

設定：

```text
高精度測位：使用しない
タイムアウト：5秒
位置情報キャッシュ：最大1時間
```

住所判定：

```text
https://mreversegeocoder.gsi.go.jp/reverse-geocoder/LonLatToAddress
```

初回表示時に一度だけGPS取得を試みます。許可されない場合は東京都を初期地点として表示し、手動選択も利用可能にします。

### 6.5 雨雲レーダー

RainViewerを埋め込みます。

```text
https://www.rainviewer.com/map.html?loc={緯度},{経度},8&layer=radar
```

選択地点が変わったら、緯度・経度を変更してiframeを再読み込みします。

## 7. データ処理ルール

### 7.1 天気コードの表示

| weather_code | 表示 | アイコン |
|---|---|---|
| 0〜1 | 晴れ | ☀️ |
| 2〜3 | くもり | ☁️ |
| 4〜57 | 霧・霧雨 | 🌫️ |
| 58〜67 | 雨 | 🌧️ |
| 68〜77 | 雪 | 🌨️ |
| 78〜82 | にわか雨 | 🌦️ |
| 83以上 | 雷雨 | ⛈️ |

### 7.2 平均値

数値が取得できたモデルのみを対象とします。

```text
平均値 = 有効なモデルの数値合計 ÷ 有効なモデル数
```

- 気温と降水確率：画面では原則整数に丸める
- 1時間降水量と風速：小数第1位まで表示
- 欠損モデルを0として計算しない
- 有効モデル数を `3/4モデル` のように表示する

### 7.3 多数派の天気

各モデルの天気コードを天気分類へ変換し、最も多い分類を総合天気とします。

例：

```text
晴れ、晴れ、くもり、晴れ
→ 4モデル中3モデルが晴れ
→ 総合天気は「晴れ」
```

### 7.4 傘判定

次のどちらかを満たす時間を、傘推奨時間とします。

```text
平均降水確率が40%以上
または
平均時間降水量が0.2mm以上
```

連続した対象時間を一つの時間帯にまとめます。表示する時間帯は先頭から最大2区間です。

24時間総降水量が0.5mm以上の場合も、傘が必要と判定します。

### 7.5 雨雲接近メッセージ

15分間隔の短時間降水量が0.1mm以上になる最初の時刻を探します。

```text
先頭の値が対象：現在、雨雲がかかる可能性
1つ後が対象：約15分後に接近
2つ後が対象：約30分後に接近
対象なし：今後1時間は目立った接近予測なし
```

時間降水量の目安は、15分降水量を4倍して表示します。

### 7.6 総合信頼度

100点満点で、次の重みを使用します。

| 評価項目 | 配点 |
|---|---:|
| 天気の一致 | 30 |
| 雨の開始時刻の差 | 20 |
| 雨の終了時刻の差 | 10 |
| 24時間降水量の差 | 15 |
| 気温の差 | 15 |
| 最大風速の差 | 10 |
| 合計 | 100 |

ばらつきの点数は次の考え方で0〜1へ正規化します。

```text
score = 1 - (最大値 - 最小値 - 良好差) ÷ (不良差 - 良好差)
```

0未満は0、1を超えた場合は1にします。データがない項目は暫定的に0.5とします。

基準値：

| 項目 | 良好差 | 不良差 |
|---|---:|---:|
| 雨開始 | 1時間 | 6時間 |
| 雨終了 | 1時間 | 6時間 |
| 降水量 | 1mm | 10mm |
| 気温 | 2℃ | 8℃ |
| 風速 | 3km/h | 15km/h |

星表示は `信頼度 ÷ 20` を四捨五入し、1〜5個で表示します。

### 7.7 週間天気の信頼度

- 4モデルの天気が一致し、最高気温差が2.5℃以内：`信頼度 高`
- 一致モデルが半数以下、または最高気温差が5℃以上：`予報が不安定`
- それ以外：`信頼度 中`

### 7.8 総合コメント

雨がある場合：

```text
今日は22時ごろから雨。傘を持って。
```

雨がない場合：

```text
今日は晴れ。傘なしで過ごせそうです。
```

断定ではなく、「可能性」「見込み」など予報であることが分かる表現を使用します。


左幅は約520〜620px、右側は残りの幅を使用します。

### 8.3 スマートフォン表示

1カラムで、重要な結論を先に表示します。文字は原則14px以上、主要な数値は20px以上、操作ボタンは高さ44px以上を確保します。

4モデル比較は週間天気の下へ配置します。24時間の詳細は横スクロールで確認できるようにします。

### 8.4 天気別の背景

| 天気 | 背景色 |
|---|---|
| 晴れ | オレンジ〜黄色 |
| くもり・霧 | 濃いグレー |
| 雨・にわか雨 | 青 |
| 雪 | 水色 |
| 雷雨 | 紫〜青 |

文字は白を基本とし、曇り背景は十分に濃くしてコントラストを確保します。

## 9. 状態管理

主な状態：

| 状態 | 内容 |
|---|---|
| `pref` | 選択中の都道府県 |
| `region` | 選択中の地方 |
| `day` | 今日または明日 |
| `forecast` | Open-Meteoの予報データ |
| `selectedPlace` | 市区町村・GPS地点 |
| `warningStatus` | 警報・注意報 |
| `shortRain` | 15分間隔の降水予測 |
| `placeResults` | 地点検索結果 |
| `locationLoading` | GPS取得中かどうか |

地点が変わった場合、予報・短時間降水・警報・レーダーをすべて同じ地点へ更新します。

## 10. 更新仕様

- 初回表示時にデータを取得
- 地点変更時に再取得
- 今日・明日の切り替え時は取得済みデータから表示変更
- 1時間ごとにページを再読み込みして最新データを取得
- 更新時刻は日本時間で表示

## 11. エラー処理

| 状況 | 表示・動作 |
|---|---|
| 天気API失敗 | 取得失敗メッセージを表示 |
| GPS非対応 | 対応していない旨を表示 |
| GPS拒否 | 端末設定から許可する案内を表示 |
| GPSタイムアウト | 再試行を案内し、既定地点を維持 |
| 地点が見つからない | 該当地点なしと表示 |
| 警報API失敗 | 気象庁公式情報への確認を案内 |
| レーダー読込遅延 | 通信状況による旨を表示 |
| 一部モデル欠損 | 有効データ数を表示して計算を継続 |

## 12. セキュリティ・注意事項

- APIキー、パスワード、短期認証トークンをGitHubへ保存しない
- 外部リンクは新しいタブで開き、`rel="noreferrer"` を指定する
- GPSは利用者が許可した場合だけ使用する
- 緯度・経度をサイト側のデータベースへ保存しない
- 天気予報を防災上の確定情報として表現しない
- 警報・避難情報は気象庁や自治体の公式情報を優先する

## 17. AIへ実装を依頼する場合の指示文

```text
添付した「KMG天気予報 実装設計書」を仕様の参考資料として読み、
React、TypeScript、Tailwind CSSで天気予報サイトを実装してください。

設計書に記載された4モデル、API、計算基準、画面順、
PC・スマートフォンの配置、エラー処理、テスト項目を守ってください。

最初はローカルだけで実装し、npm run buildを実行してください。

```

AIにはこの設計書だけでなく、完成画面のスクリーンショットと既存のGitHubリポジトリも渡すと、再現精度が上がります。
